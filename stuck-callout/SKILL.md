# Stuck Callout

当你（agent）在穿越 terrain 时偏离了路线、原地打转、或无法继续前进，生成一份*迷航信号*。这份信号的目标是让人类**不需要翻阅前面的对话历史**，就能快速理解你偏到了哪里、为什么偏的、需要什么救援。

## 何时触发

两种模式下触发：

1. **用户手动触发** — 用户说"卡住了" / "stuck" / "你卡住了" / "出了什么问题" / "你在干什么" / "什么情况" 等，直接发射信号。
2. **Agent 自检触发** — 当你发现以下迷航信号时，主动发射 distress signal：
   - 同一函数/文件/工具被反复调用 3+ 次但无明显进展（**原地打转**）
   - 尝试了 2+ 种不同路线但都走不通
   - 连续收到非预期的错误或异常
   - 输出结果明显不正确但无法定位根因
   - 某个步骤阻塞了 5+ 轮交互

## 输出模板

ALWAYS 使用以下结构化模板输出（渲染为 Markdown）：

```
## ⛔ 迷航信号：<一句话概括当前偏离>

### 1. 目标航向
<原任务的一句话描述>

### 2. 已试路线

| # | 路线 | 结果 |
|---|------|------|
| 1 | <走了什么路线> | <走不通/部分通过/不确定> |
| 2 | <走了什么路线> | <走不通/部分通过/不确定> |

### 3. 估算位置
- <我认为偏离的原因 1>
- <我认为偏离的原因 2>

### 4. 偏离根因
<直击核心的一句话。如果是用户手动触发的，说明此前的航向中哪一步偏了>

### 5. 需要救援
- [ ] <具体需要人类确认/决定/提供的信息 1>
- [ ] <具体需要人类确认/决定/提供的信息 2>

### 6. 如果无人救援，下一步会怎么走
<如果人类不介入，计划的下一个尝试>
```

## 执行流程

### Step 1 — 收集上下文

回顾当前会话中的关键信息：

- 原始任务描述（目标航向）
- 已经走过的路线（列出每条路线的核心思路和结果）
- 当前对偏离的理解/估算位置
- 如果需要，查看最近的调试输出、错误信息、文件内容来确认状态

Do not proceed until you have concrete items for each section.

### Step 2 — 填充信号

按照上述模板填写。注意：

- **已试路线**只填关键路线，不要列出所有细微的调试步骤。3-5 行足够。
- **估算位置**需要诚实：如果不确定偏离原因是什么就说"不确定"。
- **偏离根因**要具体，不是"代码有 bug"，而是"XXX 函数的类型签名与调用处的实际参数不匹配"。
- **需要救援**必须是可以行动的问题，不是"帮我看看"——而是"帮我确认 XXX 参数应该是 string 还是 Buffer"。
- **下一步**可以写"暂无思路"——承认不知道比假装有下一步更好。

### Step 3 — 发射信号

打印完整的迷航信号给用户。**不要添加额外评论、道歉或解释。** 信号是最小的刚好够用的格式。

- [ ] 所有 6 个章节都有实质性内容
- [ ] "需要救援"的每一项都是可行动的
- [ ] 没有冗余段落或无关信息
