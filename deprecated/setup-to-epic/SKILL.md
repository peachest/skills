# Setup to-epic — Issue Tracker Integration

Add Milestone / Feature directory conventions to the project's issue tracker config
so `to-epic`, `to-prd`, and `to-issues` all understand the file layout.

## Process

### 1. Check existing config

Read `docs/agents/issue-tracker.md`. Look for a section containing the anchor
`## Milestone / Feature — to-epic` or similar text describing the two-level
directory structure.

- [ ] issue-tracker.md read

If found → already configured. Do nothing.

If not found → proceed to Step 2.

### 2. Append hierarchy section

**Do not proceed until Step 1 is complete.** Add the following section to the
end of `docs/agents/issue-tracker.md`:

```markdown
## Milestone / Feature — to-epic

When to-epic skill runs, it creates a two-level directory structure under
`.scratch/`:

```
.scratch/
├── README.md                          ← index of all milestones and features
├── <milestone-slug>/
│   ├── epic.md                        ← milestone overview
│   ├── <feature-slug>/
│   │   ├── feature.md                 ← Feature scope (input for to-prd)
│   │   ├── PRD.md                     ← ← generated by to-prd
│   │   └── issues/                    ← ← generated by to-issues
│   │       ├── 01-<slug>.md
│   │       └── 02-<slug>.md
│   └── <another-feature-slug>/
│       └── ...
└── <another-milestone-slug>/
    └── ...
```

**Conventions:**

- `epic.md` — milestone overview with Scope, Rationale, Features table, and
  dependencies. Human-facing — not an input for to-prd.
- `feature.md` — single-Feature scope description. Input for to-prd.
  Contains Scope, Rationale, Acceptance Criteria (high-level), Dependencies,
  and Source sections. Kept lean — no user stories, no implementation decisions.
- `PRD.md` — full PRD, generated by to-prd from feature.md.
- `issues/` — task-level issues, generated by to-issues from PRD.md.

**Pipeline:**

```
idea.md → to-epic → feature.md → to-prd → PRD.md → to-issues → issues/
                ↘ epic.md (milestone overview)
```

### Why two levels?

A **milestone** (MVP, Phase 2, …) can contain multiple features (data layer,
commands, TUI). Each feature is independently spec-able, so each gets its own
feature.md. The milestone-level epic.md provides the glue: scope, rationale,
and which features it contains.
```

### 3. Confirm

Tell the user the issue tracker config has been updated with Milestone/Feature
hierarchy info.

- [ ] User notified of config update
