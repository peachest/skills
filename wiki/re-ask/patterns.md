# re-ask patterns

## P-001 提问缺隐含上下文（重问 9 连发）
- 状态: absorbed-into-skill
- 现象: 用户对 agent 的提问回复「重新问问题」「什么开放点」，同一形态跨多 session 复发（同一项目 5 天内 9 次裸触发「重新问问题，什么开放点？」）
- 根因: agent 即兴——提问只对提问方上下文可读（引用上轮状态不重述 / 问题埋在长报告末尾），无契约要求问题自带背景
- 方案: re-ask skill 分支一（四段中立模板：背景/已知/隐含的问题/答案影响），仅手动触发；agent 侧预防建议后续写 AGENTS.md 一句话规则
- 触发条件: 用户消息匹配「重新问」
- passCheck: 重问产出含四段结构且无「上一轮/如前所述」指代
- 证据: 01a07b18, 01a03e1c, 01a023e5, 01a15451, 01a15a56, 01a15e70, 01a15e93, 019ef778, 01a17ee0（均无 entry 级定位，见挖掘产物 ~/tmp/implicit-question-mining/reask-pairs.json，本地留存）
- 出现: 2026-10-30 知识提取（session-mining 全库挖掘）

## P-002 产出需重解释（概念/公式/进度，频次为重问 2 倍）
- 状态: absorbed-into-skill
- 现象: 「大白话解释」「重新说明」「展开说」类纠偏 104+15 次（概念解释 104 为最大头）；病根是用术语解释术语、压缩术语、隐喻
- 根因: agent 即兴——产出默认读者共享作者的术语共建过程
- 方案: re-ask skill 分支二（三段模板：在哪用/指什么/为什么需要它）+ 红线（术语定义术语/隐喻/压缩术语三项为零）
- 触发条件: 用户消息匹配「大白话」「重新解释」「重新说明」「看不懂」
- passCheck: 重解释产出定义句中无未解释术语、隐喻计数为 0
- 证据: 01a15220, 01a15409, 01a15451, 01a0aeb3, 01a12e18, 01a0d2cb, 01a0d183（同上，~/tmp/implicit-question-mining/user-instructions-broad.json）
- 出现: 2026-10-30 知识提取

## P-003 进度重述不属于重问域（边界记录）
- 状态: absorbed-into-skill（以边界声明形式吸收）
- 现象: 「大白话说明当前剩余任务」跨 8 session 出现 10 次；「你把我搞混了，完全不知道你在干什么」3 次
- 根因: 知识提取——这是重入场需求（orient/日报域），不是对单条产出的重写；强行进 re-ask 会职责重叠
- 方案: re-ask SKILL.md「边界」节显式拒接并指路 orient；进度四要素（在哪/已定/暂定/剩什么）留 orient 吸收
- 触发条件: 人工判定
- passCheck: 用户说「说明剩余任务」时不触发 re-ask 而指路 orient
- 证据: 01a15451, 01a15a56, 01a15e70, 01a15e93, 01a12e18, 01a15a2f, 01a15cd0, 01a15e79, 01a1780e
- 出现: 2026-10-30 知识提取

## P-004 peer 修复先例（模板正典来源）
- 状态: absorbed-into-skill
- 现象: 客户答疑会问题清单被用户点破「问题建立在 agent 已知的 Facts 和暂定方案上，读者并不知道」；peer agent 将每题重构为四段式 + §0 现状速览后直接可用
- 根因: agent 即兴（同 P-001 的文档场景形态）
- 方案: 四段式 + 现状速览被 re-ask 分支一吸收为文档模式规范；「重要分歧点不要只问同不同意，要问有没有反对意见」作为隐含信息显式化的补充口径
- 触发条件: 人工判定
- passCheck: 文档模式产出含现状速览节（3 题以上时）
- 证据: 01a17c70（peer session 尾轮，write customer-meeting-questions.md 及 STATE 同步两 entry）
- 出现: 2026-10-30 知识提取

## P-005 四段模板双层正典归属
- 状态: absorbed-into-skill
- 现象: 同一四段模板存在两处措辞正典——AGENTS.md 提问规则节（预防层，第二人称「为什么现在问/已经知道什么」）与 re-ask SKILL.md 分支一（修复层，中立「背景/已知」）；语义同源、字面已分叉
- 根因: 知识提取——双层设计是故意的（提问前预防 vs 被点名后修复，读者与时机不同），但缺归属声明会真漂移
- 方案: 正典归属 = AGENTS.md 管预防层措辞、SKILL.md 管修复层措辞；改任一侧模板字段时必须双向同步并对照本条；红线条目（禁引用上轮/术语定义术语/隐喻/超意图）以 SKILL.md 为正典，AGENTS.md 只保留与提问直接相关的子集
- 触发条件: grep「为什么现在问」或「分支一」命中任一文件即为考到
- passCheck: 两处四段字段的语义一一对应（背景↔为什么现在问、已知↔已经知道什么、隐含的问题、答案影响）
- 证据: 01a1814f（re-ask 新建与 AGENTS.md 提问规则节同 session 落地）
- 出现: 2026-10-30 知识提取
