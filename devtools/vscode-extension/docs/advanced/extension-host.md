			<main class="docs-main-content body"><h1>Extension Host</h1>
<p>The <strong>Extension Host</strong> is responsible for running extensions.</p>
<h2 id="extension-host-configurations" data-needslink="extension-host-configurations">Extension Host configurations</h2>
<p>Depending on the configuration of VS Code, there are multiple extension hosts running, with different runtimes, at different locations.</p>
<ul><li>local – A Node.js extension host running locally, on the same machine as the user interface.</li>
<li>web – A web extension host running in the browser or locally, on the same machine as the user interface.</li>
<li>remote – A Node.js extension host running remotely in a container or a remote location.</li>
</ul><p>The following table shows which extension hosts are available in the various configurations of VS Code:</p>
<table class="table table-striped"><thead><tr><th>Configuration</th>
<th>local extension host</th>
<th>web extension host</th>
<th>remote extension host</th>
</tr></thead><tbody><tr><td>VS Code on the desktop</td>
<td>✔️</td>
<td>✔️</td>
<td></td>
</tr><tr><td><a href="/docs/remote/remote-overview">VS Code with remote</a> (Container, SSH, WSL, GitHub Codespace, Tunnel)</td>
<td>✔️</td>
<td>✔️</td>
<td>✔️</td>
</tr><tr><td>VS Code for the Web (vscode.dev, github.dev)</td>
<td></td>
<td>✔️</td>
<td></td>
</tr><tr><td>VS Code for the Web with Codespaces</td>
<td></td>
<td>✔️</td>
<td>✔️</td>
</tr></tbody></table><h3 id="extension-host-runtimes" data-needslink="extension-host-runtimes">Extension Host runtimes</h3>
<ul><li>Node.js - Extensions are running in a Node.js runtime. Used by the local and remote extension hosts. Extensions need a <code>main</code> entry file to run in it.</li>
<li>Browser - Extensions are running in <a href="https://developer.mozilla.org/docs/Web/API/Web_Workers_API" class="external-link" target="_blank">Browser WebWorker</a> runtime. Used by the web extension host. Extensions need a <code>browser</code> entry file to run in it. See the <a href="/api/extension-guides/web-extensions">Web extensions guide</a> for more details.</li>
</ul><h3 id="preferred-extension-location" data-needslink="preferred-extension-location">Preferred extension location</h3>
<p>The extension host where an extension is loaded depends on:</p>
<ul><li>The available extension hosts given by the configuration of VS Code.</li>
<li>The capabilities of the extension: Can it run in Node.js, and/or the web, or if not indicated, what contributions does it provide?</li>
<li>Where is the extension installed: On the local machine, on the remote machine, or both.</li>
<li>The location the extension prefers: the <code>extensionKind</code> property.</li>
</ul><p><code>extensionKind</code> is a property in the <a href="/api/references/extension-manifest">extension manifest</a>. It allows extensions to specify a preferred running location. That can be the machine that has the workspace (<code>workspace</code>) or the user interface (<code>ui</code>). If an extension can run on both, it can specify an order of preference.</p>
<ul><li><code>"extensionKind": ["workspace"]</code> — Indicates the extension requires access to workspace contents and therefore needs to run where the workspace is located. That can be on the local machine or on the remote machine or Codespace. Most extensions fall into this category.</li>
<li><code>"extensionKind": ["ui", "workspace"]</code> — Indicates the extension <strong>prefers</strong> to run as a UI extension, but does not have any hard requirements on local assets, devices, or capabilities. When using VS Code, the extension will run in VS Code's local extension host if it exists locally and means the user does not have to install the extension on the remote. Otherwise, the extension will run in VS Code's workspace extension host if it exists there. When using VS Code for the Web with Codespaces, it will run in the remote extension host always (as no local extension host is available).</li>
<li><code>"extensionKind": ["workspace", "ui"]</code> — Indicates the extension <strong>prefers</strong> to run as a workspace extension, but does not have any hard requirements on accessing workspace contents. When using VS Code, the extension will run in VS Code's workspace extension host if it exists in remote workspace, otherwise will run in VS Code's local extension host if it exists locally. When using VS Code for the Web with Codespaces it will run in the remote extension host always (as no local extension host is available).</li>
<li><code>"extensionKind": ["ui"]</code> — Indicates the extension <strong>must</strong> run close to the UI because it requires access to local assets, devices, or capabilities or because low latency is required. In the case of VS Code for the Web with Codespaces, where no local extension host is available, such an extension can not load, unless it is also a <a href="/api/extension-guides/web-extensions">web extension</a>. It will then be loaded in the web extension host with a limitation that it cannot instantiate a web worker.</li>
</ul><p><strong>Note:</strong> Prior VS Code releases (&lt;1.40) allowed an extension to specify a single location as a string but this is deprecated in favor of multiple locations as an array.</p>
<p>If an extension can run on Node.js and in the browser, a Node.js extension host will be selected if available. There's one exception, when the configuration is VS Code for the Web with Codespaces and the <code>extensionKind</code> is set to <code>ui</code>, then the web extension host is preferred over the remote extension host.</p>
<p>If an extension is web-only, it will always run on the web extension host, regardless of the <code>extensionKind</code> setting. We recommend to not define <code>extensionKind</code> in that case.</p>
<h2 id="stability-and-performance" data-needslink="stability-and-performance">Stability and Performance</h2>
<p>VS Code aims to deliver a stable and high performance editor to users, and misbehaving extensions should not impact the user experience. The Extension Host in VS Code prevents extensions from:</p>
<ul><li>Impacting startup performance</li>
<li>Slowing down UI operations</li>
<li>Modifying the UI</li>
</ul><p>Additionally, VS Code lets extensions declare their <a href="/api/references/activation-events">Activation Events</a> and loads them lazily. For example, the Markdown extension should only be loaded when a user opens a Markdown file. This makes sure that extensions do not consume unnecessary CPU and memory.</p>
