			<main class="docs-main-content body"><h1>UX Guidelines</h1>
<p>These guidelines cover the best practices for creating extensions that seamlessly integrate with VS Code's native interface and patterns. In these guidelines, you can expect to find:</p>
<ul><li>An outline of VS Code's overall UI architecture and elements</li>
<li>Recommendations and examples for UI contributed by an extension</li>
<li>Links to relevant guides and samples</li>
</ul><p>Before diving into the details, it's important to understand how the various architectural UI parts of VS Code fit together and how and where your extension could contribute.</p>
<h2 id="containers" data-needslink="containers">Containers</h2>
<p>The VS Code interface can roughly be divided into two main concepts: <strong>containers</strong> and <strong>items</strong>. Generally speaking, containers can be considered the larger sections of the VS Code interface that render one or more items:</p>
<p><a href="/assets/api/ux-guidelines/examples/architecture-containers.png"><img src="/assets/api/ux-guidelines/examples/architecture-containers.png" alt="Overview of Visual Studio Code containers elements" loading="lazy"></a></p>
<h3 id="activity-bar" data-needslink="activity-bar">Activity Bar</h3>
<p>The <a href="/api/ux-guidelines/activity-bar">Activity Bar</a> is a core navigation surface in VS Code. Extensions can contribute items to the Activity Bar that function as <a href="/api/references/contribution-points#contributes.viewsContainers">View Containers</a> that render <a href="/api/ux-guidelines/views">Views</a> in the Primary Sidebar.</p>
<h3 id="primary-sidebar" data-needslink="primary-sidebar">Primary Sidebar</h3>
<p>The <a href="/api/ux-guidelines/sidebars#primary-sidebar">Primary Sidebar</a> renders one or more <a href="/api/ux-guidelines/views">Views</a>. The Activity Bar and the Primary Sidebar are tightly coupled. Clicking on a contributed Activity Bar Item (read: View Container) opens up the Primary Sidebar where one or more View associated with that View Container will be rendered. A concrete example would be the Explorer. Clicking on the Explorer Item will open up the Primary Sidebar where the Folder(s), Timeline, and Outline Views are visible.</p>
<h3 id="secondary-sidebar" data-needslink="secondary-sidebar">Secondary Sidebar</h3>
<p>The <a href="/api/ux-guidelines/sidebars#secondary-sidebar">Secondary Sidebar</a> also functions as a surface for rendering a View Container with Views. Users can drag views like the Terminal or the Problems view to the Secondary Sidebar to customize their layout.</p>
<h3 id="editor" data-needslink="editor">Editor</h3>
<p>The Editor area contains one or more Editor Groups. Extensions can contribute <a href="/api/references/contribution-points#contributes.customEditors">Custom Editors</a> or <a href="/api/extension-guides/webview">Webviews</a> to open in the Editor area. They can also contribute <a href="/api/ux-guidelines/editor-actions">Editor Actions</a> to expose additional icon buttons in the Editor Toolbar.</p>
<h3 id="panel" data-needslink="panel">Panel</h3>
<p>The <a href="/api/ux-guidelines/panel">Panel</a> is another area for exposing View Containers. By default, Views like the Terminal, Problems, and Output can be viewed in a single tab at a time in the Panel. Users can also drag views into a split layout much like they can do in the Editor. Additionally, extensions can choose to add View Containers specifically to the Panel instead of the Activity Bar/Primary Sidebar.</p>
<h3 id="status-bar" data-needslink="status-bar">Status Bar</h3>
<p>The <a href="/api/ux-guidelines/status-bar">Status Bar</a> provides contextual information about the workspace and currently active file. It renders two groups of <a href="/api/ux-guidelines/status-bar#status-bar-items">Status Bar Items</a>.</p>
<h2 id="items" data-needslink="items">Items</h2>
<p>Extensions can add items to the various containers listed above.</p>
<p><a href="/assets/api/ux-guidelines/examples/architecture-sections.png"><img src="/assets/api/ux-guidelines/examples/architecture-sections.png" alt="Overview of Visual Studio Code containers elements" loading="lazy"></a></p>
<h3 id="view" data-needslink="view">View</h3>
<p><a href="/api/ux-guidelines/views">Views</a> can be contributed in the form of a <a href="/api/ux-guidelines/views#tree-views">Tree View</a>, <a href="/api/ux-guidelines/views#welcome-views">Welcome View</a>, or <a href="/api/ux-guidelines/webviews#webview-views">Webview View</a> and can be dragged around to other areas of the interface.</p>
<h3 id="view-toolbar" data-needslink="view-toolbar">View Toolbar</h3>
<p>Extensions can expose View-specific <a href="/api/ux-guidelines/views#view-actions">actions</a> that appear as buttons on a View Toolbar.</p>
<h3 id="sidebar-toolbar" data-needslink="sidebar-toolbar">Sidebar Toolbar</h3>
<p>Actions scoped to an entire View Container can also be exposed in the <a href="/api/ux-guidelines/sidebars#sidebar-toolbars">Sidebar Toolbar</a>.</p>
<h3 id="editor-toolbar" data-needslink="editor-toolbar">Editor Toolbar</h3>
<p>Extensions can contribute <a href="/api/ux-guidelines/editor-actions">Editor Actions</a> scoped to an editor directly in the Editor Toolbar.</p>
<h3 id="panel-toolbar" data-needslink="panel-toolbar">Panel Toolbar</h3>
<p>The <a href="/api/ux-guidelines/panel#panel-toolbar">Panel Toolbar</a> can expose options scoped to the currently selected View. For example the Terminal view exposes actions to add a new terminal, split the view layout, and more. Switching to the Problems view exposes a different set of actions.</p>
<h3 id="status-bar-item" data-needslink="status-bar-item">Status Bar Item</h3>
<p>On the left, <a href="/api/ux-guidelines/status-bar#status-bar-items">Status Bar Items</a> are scoped to the entire Workspace. On the right, items are scoped to the active file.</p>
<h2 id="common-ui-elements" data-needslink="common-ui-elements">Common UI Elements</h2>
<h3 id="command-palette" data-needslink="command-palette">Command Palette</h3>
<p>Extensions can contribute Commands that appears in the <a href="/api/ux-guidelines/command-palette">Command Palette</a> to quickly execute some functionality.</p>
<p><a href="/assets/api/ux-guidelines/examples/command-palette.png"><img src="/assets/api/ux-guidelines/examples/command-palette.png" alt="Overview of the Command Palette element" loading="lazy"></a></p>
<h3 id="quick-pick" data-needslink="quick-pick">Quick Pick</h3>
<p><a href="/api/ux-guidelines/quick-picks">Quick Picks</a> capture a user's input in several different ways. They can ask for a single selection, multiple selections, or even freeform text input.</p>
<p><img src="/assets/api/ux-guidelines/examples/quick-pick.png" alt="Overview of the Quick Pick element" loading="lazy"></p>
<h3 id="notifications" data-needslink="notifications">Notifications</h3>
<p><a href="/api/ux-guidelines/notifications">Notifications</a> are used to communicate information, warning, and error messages to users. They can also be used to indicate progress.</p>
<p><img src="/assets/api/ux-guidelines/examples/notification.png" alt="Overview of the Notification element" loading="lazy"></p>
<h3 id="webviews" data-needslink="webviews">Webviews</h3>
<p><a href="/api/ux-guidelines/webviews">Webviews</a> can be used to display custom content and functionality for use cases that go beyond VS Code's "native" API.</p>
<p><img src="/assets/api/ux-guidelines/examples/webview.png" alt="Overview of the Webview element" loading="lazy"></p>
<h3 id="context-menus" data-needslink="context-menus">Context Menus</h3>
