			<main class="docs-main-content body"><h1>Sidebars</h1>
<p>The Primary and Secondary Sidebars consists of one or more <a href="/api/ux-guidelines/views">Views</a> contributed by a <a href="/api/ux-guidelines/views#view-containers">View Container</a>. Extensions can contribute Views to an existing View Container (for example, Explorer) or they can contribute an entirely new View Container.</p>
<p><strong>✔️ Do</strong></p>
<ul><li>Group related Views and content together</li>
<li>Use clear, descriptive names for View Containers and their Views</li>
</ul><p><strong>❌ Don't</strong></p>
<ul><li>Use an excessive number of View Containers. A single View Container (such as a Sidebar with Views unique to that extension) is generally enough for most extensions.</li>
<li>Use an excessive number of Views (3-5 is a comfortable max for most screen sizes)</li>
<li>Add content to the Sidebar that could be a simple Command.</li>
<li>Repeat existing functionality</li>
</ul><p><img src="/assets/api/ux-guidelines/examples/sidebars.png" alt="Example of two sidebars" loading="lazy"></p>
<h2 id="primary-sidebar" data-needslink="primary-sidebar">Primary Sidebar</h2>
<p>Many extensions choose to contribute Views and/or View Containers to the Primary Sidebar given the high visibility it gives content. Use good judgement when adding content here—too much contributed UI can lead to a cluttered experience that can confuse your users.</p>
<p><img src="/assets/api/ux-guidelines/examples/primary-sidebar.png" alt="Example of the primary sidebar" loading="lazy"></p>
<h2 id="secondary-sidebar" data-needslink="secondary-sidebar">Secondary Sidebar</h2>
<p>As the name implies, the Secondary Sidebar is normally considered a auxiliary location for Views. While extensions cannot contribute Views directly to it by default, users can drag Views from the Primary Sidebar or the Panel to customize their layout.</p>
<p><img src="/assets/api/ux-guidelines/examples/secondary-sidebar.png" alt="Example of the secondary sidebar" loading="lazy"></p>
<h2 id="sidebar-toolbars" data-needslink="sidebar-toolbars">Sidebar Toolbars</h2>
<p>By default, View Containers in the Sidebar with more than one View will feature a single <code>...</code> icon button in the Sidebar Toolbar to show and hide each View. That looks something like this:</p>
<p><img src="/assets/api/ux-guidelines/examples/sidebar-toolbar-default.png" alt="Sidebar with two views" loading="lazy"></p>
<p>However, if only one View is used, the Sidebar will automatically consolidate the UI to use the Sidebar Toolbar to render all of the actions specific to that View. In place of the <code>...</code> button, the two actions associated with the 'Notes' View are rendered in its place:</p>
<p><img src="/assets/api/ux-guidelines/examples/sidebar-toolbar-actions.png" alt="Sidebar with a single view and toolbar with actions" loading="lazy"></p>
<p>As with other toolbars, be careful to not add too many actions to reduce clutter and confusion. If possible, use an existing product icon paired with a descriptive Command name.</p>
