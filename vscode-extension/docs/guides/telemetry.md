			<main class="docs-main-content body"><h1>Telemetry extension authors guide</h1>
<p>Visual Studio Code collects usage data and sends it to Microsoft to help improve our products and services. Read our <a href="https://go.microsoft.com/fwlink/?LinkID=528096&amp;clcid=0x409" class="external-link" target="_blank">privacy statement</a> and <a href="/docs/getstarted/telemetry">telemetry documentation</a> to learn more.</p>
<p>This topic has guidelines for extension authors so that their extensions can conform to VS Code telemetry requirements and best practices.</p>
<blockquote><p><strong>Note</strong>: If you don't want to send usage data to Microsoft, you can set the <code>telemetry.telemetryLevel</code> user <a href="/docs/configure/settings">setting</a> to <code>off</code>.</p>
</blockquote><h2 id="telemetry-module" data-needslink="telemetry-module">Telemetry module</h2>
<p>The VS Code team maintains the <a href="https://www.npmjs.com/package/@vscode/extension-telemetry" class="external-link" target="_blank">@vscode/extension-telemetry</a> npm module that provides a consistent and safe way to collect telemetry within VS Code. The module reports telemetry to <a href="https://azure.microsoft.com/services/monitor/" class="external-link" target="_blank">Azure Monitor and Application Insights</a> and guarantees backwards compatibility against previous versions of VS Code.</p>
<p>Follow this guide to set up <a href="https://learn.microsoft.com/azure/azure-monitor/app/nodejs" class="external-link" target="_blank">Azure Monitor</a> and get your Application Insights instrumentation key.</p>
<h2 id="without-the-telemetry-module" data-needslink="without-the-telemetry-module">Without the telemetry module</h2>
<p>Extension authors who wish not to use Application Insights can utilize their own custom solution to send telemetry. In this case, it is still required that extension authors respect the user's choice by utilizing the <code>isTelemetryEnabled</code> and <code>onDidChangeTelemetryEnabled</code> API. By doing this, users will have one centralized place to control their telemetry settings.</p>
<h2 id="custom-telemetry-setting" data-needslink="custom-telemetry-setting">Custom telemetry setting</h2>
<p>Extension may wish to give user control for extension specific telemetry independent of VS Code telemetry. In this case, we suggest that you introduce a specific extension setting. It is recommended that custom telemetry settings be tagged with <code>telemetry</code> and <code>usesOnlineServices</code> so that users can more easily query them in the Settings UI. Adding a custom telemetry setting is not an exemption from respecting a user's decision and the <code>isTelemetryEnabled</code> and <code>onDidChangeTelemetryEnabled</code> flag must always be respected. If <code>isTelemetryEnabled</code> reports false, even if your setting is enabled, telemetry must not be sent.</p>
<h2 id="telemetry.json" data-needslink="telemetry.json">telemetry.json</h2>
<p>We understand that telemetry can be a sensitive topic for many users and we aim to be as transparent as possible. The core VS Code product and most first party extensions ship with a <code>telemetry.json</code> file in their root. This allows a user to use the VS Code CLI with the <code>--telemetry</code> flag to receive a dump of all telemetry that VS Code produces. Extension authors may include a <code>telemetry.json</code> file in their root and it will also appear in the CLI dump.</p>
<h2 id="dos-and-donts" data-needslink="dos-and-donts">Do's and Don'ts</h2>
<p>✔️ Do</p>
<ul><li>Use the <a href="https://www.npmjs.com/package/@vscode/extension-telemetry" class="external-link" target="_blank">@vscode/extension-telemetry</a> npm module if using application insights works for you.</li>
<li>Otherwise, respect the <code>isTelemetryEnabled</code> and <code>onDidChangeTelemetryEnabled</code> API.</li>
<li>Tag your custom telemetry setting with <code>telemetry</code> and <code>usesOnlineServices</code> if you have one.</li>
<li>Collect as little telemetry as possible.</li>
<li>Be as transparent as possible to your users about what you collect.</li>
</ul><p>❌ Don't</p>
<ul><li>Introduce a custom telemetry collection solution that does not ask for user consent.</li>
<li>Collect Personally identifiable information (PII).</li>
<li>Collect more telemetry than necessary.</li>
<li>Use just the <code>telemetry.telemetryLevel</code> setting, as it can sometimes be incorrect compared to <code>isTelemetryEnabled</code>.</li>
</ul><div class="feedback" data-edit-url="https://vscode.dev/github/microsoft/vscode-docs/blob/main/api/extension-guides/telemetry.md"></div>
