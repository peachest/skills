			<main class="docs-main-content body"><h1>when clause contexts</h1>
<p>Visual Studio Code sets various context keys and specific values depending on what elements are visible and active in the VS Code UI. These contexts can be used to selectively enable or disable extension commands and UI elements, such as menus and views.</p>
<p>For example, VS Code uses when clauses to enable or disable command keybindings, which you can see in the Default Keybindings JSON (<strong>Preferences: Open Default Keyboard Shortcuts (JSON)</strong>):</p>
<pre class="shiki" data-lang="json" shiki-themes dark-plus light-plus" style="--shiki-dark:#D4D4D4;--shiki-light:#000000;--shiki-dark-bg:#1E1E1E;--shiki-light-bg:#FFFFFF" tabindex="0"><code><span class="line"><span style="--shiki-dark:#D4D4D4;--shiki-light:#000000">{ </span><span style="--shiki-dark:#9CDCFE;--shiki-light:#0451A5">"key"</span><span style="--shiki-dark:#D4D4D4;--shiki-light:#000000">: </span><span style="--shiki-dark:#CE9178;--shiki-light:#A31515">"f5"</span><span style="--shiki-dark:#D4D4D4;--shiki-light:#000000">,  </span><span style="--shiki-dark:#9CDCFE;--shiki-light:#0451A5">"command"</span><span style="--shiki-dark:#D4D4D4;--shiki-light:#000000">: </span><span style="--shiki-dark:#CE9178;--shiki-light:#A31515">"workbench.action.debug.start"</span><span style="--shiki-dark:#D4D4D4;--shiki-light:#000000">,</span></span>
<span class="line"><span style="--shiki-dark:#9CDCFE;--shiki-light:#0451A5">                   "when"</span><span style="--shiki-dark:#D4D4D4;--shiki-light:#000000">: </span><span style="--shiki-dark:#CE9178;--shiki-light:#A31515">"debuggersAvailable &amp;&amp; !inDebugMode"</span><span style="--shiki-dark:#D4D4D4;--shiki-light:#000000"> },</span></span>
<span class="line"></span></code></pre>
<p>Above, the built-in <strong>Start Debugging</strong> command has the keyboard shortcut <span class="dynamic-keybinding" data-commandid="workbench.action.debug.start" data-osx="F5" data-win="F5" data-linux="F5"><span class="keybinding">F5</span></span>, which is only enabled when there is an appropriate debugger available (context key <code>debuggersAvailable</code> is true) and the editor isn't in debug mode (context key <code>inDebugMode</code> is false).</p>
<h2 id="conditional-operators" data-needslink="conditional-operators">Conditional operators</h2>
<p>A when clause can consist of a context key (for example, <code>inDebugMode</code>) or can use various operators to express more nuanced editor state.</p>
<h3 id="logical-operators" data-needslink="logical-operators">Logical operators</h3>
<p>Logical operators allow combining simple context keys or when-clause expressions that include other logical, equality, comparison, match, <code>in</code>/<code>not in</code> operators or parenthesized expressions.</p>
<table class="table table-striped"><thead><tr><th>Operator</th>
<th>Symbol</th>
<th>Example</th>
</tr></thead><tbody><tr><td>Not</td>
<td><code>!</code></td>
<td><code>"!editorReadonly"</code> or <code>"!(editorReadonly || inDebugMode)"</code></td>
</tr><tr><td>And</td>
<td><code>&amp;&amp;</code></td>
<td><code>"textInputFocus &amp;&amp; !editorReadonly"</code></td>
</tr><tr><td>Or</td>
<td><code>||</code></td>
<td><code>"isLinux</code><code> || </code><code>isWindows"</code></td>
</tr></tbody></table><p>Note on logical operator precedence: the above table lists operators in order of highest to lowest precedence. Examples:</p>
<table class="table table-striped"><thead><tr><th>Written as</th>
<th>Interpreted as</th>
</tr></thead><tbody><tr><td><code>!foo &amp;&amp; bar</code></td>
<td><code>(!foo) &amp;&amp; bar</code></td>
</tr><tr><td><code>!foo || bar </code></td>
<td><code>(!foo) || bar</code></td>
</tr><tr><td><code>foo || bar &amp;&amp; baz </code></td>
<td><code>foo || (bar &amp;&amp; baz)</code></td>
</tr><tr><td><code>!foo &amp;&amp; bar || baz </code></td>
<td><code>(!foo &amp;&amp; bar) || baz</code></td>
</tr><tr><td><code>!(foo || bar) &amp;&amp; baz </code></td>
<td><code>(remains same) !(foo || bar) &amp;&amp; baz</code></td>
</tr></tbody></table><h3 id="equality-operators" data-needslink="equality-operators">Equality operators</h3>
<p>You can check for equality of a context key's value against a specified value. Note that the right-hand side is a value and not interpreted as a context key, meaning it is not looked up in the context.</p>
<table class="table table-striped"><thead><tr><th>Operator</th>
<th>Symbol</th>
<th>Example</th>
</tr></thead><tbody><tr><td>Equality</td>
<td><code>==</code></td>
<td><code>"editorLangId == typescript"</code> or <code>"editorLangId == 'typescript'"</code></td>
</tr><tr><td>Inequality</td>
<td><code>!=</code></td>
<td><code>"resourceExtname != .js"</code> or <code>"resourceExtname != '.js'"</code></td>
</tr></tbody></table><p>Notes:</p>
<ul><li>If the value on the right-hand side is a string containing whitespace, it must be wrapped in single-quotes - <code>"resourceFilename == 'My New File.md'"</code>.</li>
<li><code>===</code> has the same behavior as <code>==</code>, and <code>!==</code> has the same behavior as <code>!=</code></li>
</ul><h3 id="comparison-operators" data-needslink="comparison-operators">Comparison operators</h3>
<p>You can compare a context key's value against a number. Note that left- and right-hand side of the operator must be separated by whitespace - <code>foo &lt; 1</code>, but not <code>foo&lt;1</code>.</p>
<table class="table table-striped"><thead><tr><th>Operator</th>
<th>Symbols</th>
<th>Example</th>
</tr></thead><tbody><tr><td>Greater than</td>
<td><code>&gt;</code>, <code>&gt;=</code></td>
<td><code>"gitOpenRepositoryCount &gt;= 1"</code> but not <code>"gitOpenRepositoryCount&gt;=1"</code></td>
</tr><tr><td>Less than</td>
<td><code>&lt;</code>, <code>&lt;=</code></td>
<td><code>"workspaceFolderCount &lt; 2"</code> but not <code>"workspaceFolderCount&lt;2"</code></td>
</tr></tbody></table><h3 id="match-operator" data-needslink="match-operator">Match operator</h3>
<p>(previous name: key-value pair match operator)</p>
<table class="table table-striped"><thead><tr><th>Operator</th>
<th>Symbol</th>
<th>Example</th>
</tr></thead><tbody><tr><td>Matches</td>
<td><code>=~</code></td>
<td><code>"resourceScheme =~ /^untitled$|^file$/"</code></td>
</tr></tbody></table><p>There is a match operator (<code>=~</code>) for when clauses. The expression <code>key =~ regularExpressionLiteral</code> treats the right-hand side as a regular expression literal to match against the left-hand side. For example, to contribute context menu items for all Docker files, one could use:</p>
<pre class="shiki" data-lang="json" shiki-themes dark-plus light-plus" style="--shiki-dark:#D4D4D4;--shiki-light:#000000;--shiki-dark-bg:#1E1E1E;--shiki-light-bg:#FFFFFF" tabindex="0"><code><span class="line"><span style="--shiki-dark:#CE9178;--shiki-light:#A31515">   "when"</span><span style="--shiki-dark:#D4D4D4;--shiki-light:#000000">: </span><span style="--shiki-dark:#CE9178;--shiki-light:#A31515">"resourceFilename =~ /docker/"</span></span>
<span class="line"></span></code></pre>
<p>Notes:</p>
<ul><li>The right-hand side of the <code>=~</code> operator follows the same rules as regular expression literals (<a href="https://developer.mozilla.org/docs/Web/JavaScript/Guide/Regular_Expressions#creating_a_regular_expression" class="external-link" target="_blank">reference</a>) in JavaScript, except characters need to follow escaping rules both of JSON strings and regular expressions. For example, a regular expression literal to match a substring <code>file://</code> would be <code>/file:\/\//</code> in JavaScript but <code>/file:\\/\\//</code> in a when clause because a backslash needs to be escaped in a JSON string and a slash needs to be escaped in the regular expression pattern.</li>
<li>There does not exist an operator <code>!=~</code>, but you can negate the match expression - <code>!(foo =~ /baz/)</code>.</li>
</ul><h4>Regular expression flags</h4>
<p>It is possible to use flags with the regular expression literals. For example, <code>resourceFilename =~ /json/i</code> or <code>myContextKey =~ /baz/si</code>.</p>
<p>Supported flags: <code>i</code>, <code>s</code>, <code>m</code>, <code>u</code>.</p>
<p>Ignored flags: <code>g</code>, <code>y</code>. </p>

<td>The id of the currently active <a href="/api/extension-guides/custom-editors">custom editor</a>.</td>
</tr><tr><td><strong>Configuration settings contexts</strong></td>
<td></td>
</tr><tr><td><code>config.editor.minimap.enabled</code></td>

</tr></tbody></table><blockquote><p><strong>Note</strong>: You can use any user or workspace setting that evaluates to a boolean here with the prefix <code>"config."</code>.</p>

<h2 id="check-a-setting-in-a-when-clause" data-needslink="check-a-setting-in-a-when-clause">Check a setting in a when clause</h2>
<p>In a when clause, you can reference a configuration (setting) value by prefixing it with <code>config.</code>, for example <code>config.editor.tabCompletion</code> or <code>config.breadcrumbs.enabled</code>.</p>

<h2 id="inspect-context-keys-utility" data-needslink="inspect-context-keys-utility">Inspect Context Keys utility</h2>
<p>If you would like to see all currently active context keys at runtime, you can use the <strong>Developer: Inspect Context Keys</strong> command from the Command Palette (<span class="dynamic-keybinding" data-commandid="workbench.action.showCommands" data-osx="⇧⌘P" data-win="Ctrl+Shift+P" data-linux="Ctrl+Shift+P"><span class="keybinding">⇧⌘P</span> (Windows, Linux <span class="keybinding">Ctrl+Shift+P</span>)</span>). <strong>Inspect Context Keys</strong> will display context keys and their values in the VS Code Developer Tools <strong>Console</strong> tab (<strong>Help</strong> &gt; <strong>Toggle Developer Tools</strong>).</p>
<p>When you run <strong>Developer: Inspect Context Keys</strong>, your cursor will highlight elements in the VS Code UI and when you click on an element, the current context keys and their states will be output as an object to the Console.</p>
<p><img src="/assets/api/references/when-clause-contexts/inspect-context-keys.png" alt="Inspect Context Keys output" loading="lazy"></p>
<p>The list of active context keys is extensive and may contain <a href="#_add-a-custom-when-clause-context">custom context keys</a> from extensions you have installed.</p>
<blockquote><p><strong>Note</strong>: Some context keys are for VS Code internal use and may change in the future.</p>
