			<main class="docs-main-content body"><h1>Extension Manifest</h1>
<p>Every Visual Studio Code extension needs a manifest file <code>package.json</code> at the root of the extension directory structure.</p>
<h2 id="fields" data-needslink="fields">Fields</h2>
<table class="table table-striped"><thead><tr><th>Name</th>
<th style="text-align:center">Required</th>
<th>Type</th>
<th>Details</th>
</tr></thead><tbody><tr><td><code>name</code></td>
<td style="text-align:center">Y</td>
<td><code>string</code></td>
<td>The name of the extension - should be all lowercase with no spaces.<br>The name must be unique to the Marketplace.</td>
</tr><tr><td><code>version</code></td>
<td style="text-align:center">Y</td>
<td><code>string</code></td>
<td><a href="https://semver.org/" class="external-link" target="_blank">SemVer</a> compatible version.</td>
</tr><tr><td><code>publisher</code></td>
<td style="text-align:center">Y</td>
<td><code>string</code></td>
<td>The <a href="/api/working-with-extensions/publishing-extension#publishing-extensions">publisher identifier</a></td>
</tr><tr><td><code>engines</code></td>
<td style="text-align:center">Y</td>
<td><code>object</code></td>
<td>An object containing at least the <code>vscode</code> key matching the versions of VS Code that the extension is <a href="/api/working-with-extensions/publishing-extension#visual-studio-code-compatibility">compatible</a> with. Cannot be <code>*</code>. For example: <code>^0.10.5</code> indicates compatibility with a minimum VS Code version of <code>0.10.5</code>.</td>
</tr><tr><td><code>license</code></td>
<td style="text-align:center"></td>
<td><code>string</code></td>
<td>Refer to <a href="https://docs.npmjs.com/cli/v7/configuring-npm/package-json#license" class="external-link" target="_blank">npm's documentation</a>. If you do have a <code>LICENSE</code> file in the root of your extension, the value for <code>license</code> should be <code>"SEE LICENSE IN &lt;filename&gt;"</code>.</td>
</tr><tr><td><code>displayName</code></td>
<td style="text-align:center"></td>
<td><code>string</code></td>
<td>The display name for the extension used in the Marketplace.<br>The display name must be unique to the Marketplace.</td>
</tr><tr><td><code>description</code></td>
<td style="text-align:center"></td>
<td><code>string</code></td>
<td>A short description of what your extension is and does.</td>
</tr><tr><td><code>categories</code></td>
<td style="text-align:center"></td>
<td><code>string[]</code></td>
<td>The categories you want to use for the extensions. Allowed values: <code>[Programming Languages, Snippets, Linters, Themes, Debuggers, Formatters, Keymaps, SCM Providers, Other, Extension Packs, Language Packs, Data Science, Machine Learning, Visualization, Notebooks, Education, Testing]</code></td>
</tr><tr><td><code>keywords</code></td>
<td style="text-align:center"></td>
<td><code>array</code></td>
<td>An array of <strong>keywords</strong> to make it easier to find the extension. These are included with other extension <strong>Tags</strong> on the Marketplace. This list is currently limited to 30 keywords.</td>
</tr><tr><td><code>galleryBanner</code></td>
<td style="text-align:center"></td>
<td><code>object</code></td>
<td>Helps format the Marketplace header to match your icon. See details below.</td>
</tr><tr><td><code>preview</code></td>
<td style="text-align:center"></td>
<td><code>boolean</code></td>
<td>Sets the extension to be flagged as a Preview in the Marketplace.</td>
</tr><tr><td><code>main</code></td>
<td style="text-align:center"></td>
<td><code>string</code></td>
<td>The entry point to your extension.</td>
</tr><tr><td><code>browser</code></td>
<td style="text-align:center"></td>
<td><code>string</code></td>
<td>The entry point to your <a href="/api/extension-guides/web-extensions">Web extension</a>.</td>
</tr><tr><td><a href="/api/references/contribution-points"><code>contributes</code></a></td>
<td style="text-align:center"></td>
<td><code>object</code></td>
<td>An object describing the extension's <a href="/api/references/contribution-points">contributions</a>.</td>
</tr><tr><td><a href="/api/references/activation-events"><code>activationEvents</code></a></td>
<td style="text-align:center"></td>
<td><code>array</code></td>
<td>An array of the <a href="/api/references/activation-events">activation events</a> for this extension.</td>
</tr><tr><td><code>badges</code></td>
<td style="text-align:center"></td>
<td><code>array</code></td>
<td>Array of <a href="/api/references/extension-manifest#approved-badges">approved</a> badges to display in the sidebar of the Marketplace's extension page. Each badge is an object containing 3 properties: <code>url</code> for the badge's image URL, <code>href</code> for the link users will follow when clicking the badge and <code>description</code>.</td>
</tr><tr><td><code>markdown</code></td>
<td style="text-align:center"></td>
<td><code>string</code></td>
<td>Controls the Markdown rendering engine used in the Marketplace. Either <code>github</code> (default) or <code>standard</code>.</td>
</tr><tr><td><code>qna</code></td>
<td style="text-align:center"></td>
<td><code>marketplace</code> (default), <code>string</code>, <code>false</code></td>
<td>Controls the <strong>Q &amp; A</strong> link in the Marketplace. Set to <code>marketplace</code> to enable the default Marketplace Q &amp; A site. Set to a string to provide the URL of a custom Q &amp; A site. Set to <code>false</code> to disable Q &amp; A altogether.</td>
</tr><tr><td><code>sponsor</code></td>
<td style="text-align:center"></td>
<td><code>object</code></td>
<td>Specify the location from where users can sponsor your extension. This is an object with a single property <code>url</code>, which links to a page where users can sponsor your extension.</td>
</tr><tr><td><code>dependencies</code></td>
<td style="text-align:center"></td>
<td><code>object</code></td>
<td>Any runtime Node.js dependencies your extensions needs. Exactly the same as <a href="https://docs.npmjs.com/cli/v7/configuring-npm/package-json#dependencies" class="external-link" target="_blank">npm's <code>dependencies</code></a>.</td>
</tr><tr><td><code>devDependencies</code></td>
<td style="text-align:center"></td>
<td><code>object</code></td>
<td>Any development Node.js dependencies your extension needs. Exactly the same as <a href="https://docs.npmjs.com/cli/v7/configuring-npm/package-json#devdependencies" class="external-link" target="_blank">npm's <code>devDependencies</code></a>.</td>
</tr><tr><td><code>extensionPack</code></td>
<td style="text-align:center"></td>
<td><code>array</code></td>

<h2 id="marketplace-presentation-tips" data-needslink="marketplace-presentation-tips">Marketplace Presentation Tips</h2>
<p>Here are some tips and recommendations to make your extension look great when displayed on the <a href="https://marketplace.visualstudio.com/VSCode" class="external-link" target="_blank">VS Code Marketplace</a>.</p>
<p>Always use the latest <code>vsce</code> so <code>npm install -g @vscode/vsce</code> to make sure you have it.</p>
<p>Have a <code>README.md</code> Markdown file in your extension's root folder and we will include the contents in the body of the extension details (on the Marketplace). You can provide relative path image links in the <code>README.md</code>.</p>

<h2 id="combining-extension-contributions" data-needslink="combining-extension-contributions">Combining Extension Contributions</h2>
<p>The <code>yo code</code> generator lets you easily package TextMate themes, colorizers and snippets and create new extensions. When the generator is run, it creates a complete standalone extension package for each option. However, it is often more convenient to have a single extension which combines multiple contributions. For example, if you are adding support for a new language, you'd like to provide users with both the language definition with colorization and also snippets and perhaps even debugging support.</p>
<p>To combine extension contributions, edit an existing extension manifest <code>package.json</code> and add the new contributions and associated files.</p>
<p>Below is an extension manifest which includes a LaTex language definition (language identifier and file extensions), colorization (<code>grammars</code>), and snippets.</p>

This lets VS Code know that the colorizer (<code>grammars</code>) and snippets are for the LaTeX language and will be active when editing LaTeX files.</p>
</blockquote><h2 id="extension-packs" data-needslink="extension-packs">Extension Packs</h2>
<p>You can bundle separate extensions together in <strong>Extension Packs</strong>. An Extension Pack is a set of extensions that will be installed together. This enables easily sharing your favorite extensions with other users or creating a set of extensions for a particular scenario like PHP development to help a PHP developer get started with VS Code quickly.</p>
<p>An Extension Pack bundles other extensions using the <code>extensionPack</code> attribute inside the <code>package.json</code> file.</p>
<p>For example, here is an Extension Pack for PHP that includes a debugger and a language service:</p>
<pre class="shiki" data-lang="json" shiki-themes dark-plus light-plus" style="--shiki-dark:#D4D4D4;--shiki-light:#000000;--shiki-dark-bg:#1E1E1E;--shiki-light-bg:#FFFFFF" tabindex="0"><code><span class="line"><span style="--shiki-dark:#D4D4D4;--shiki-light:#000000">{</span></span>
<span class="line"><span style="--shiki-dark:#9CDCFE;--shiki-light:#0451A5">  "extensionPack"</span><span style="--shiki-dark:#D4D4D4;--shiki-light:#000000">: [</span><span style="--shiki-dark:#CE9178;--shiki-light:#A31515">"xdebug.php-debug"</span><span style="--shiki-dark:#D4D4D4;--shiki-light:#000000">, </span><span style="--shiki-dark:#CE9178;--shiki-light:#A31515">"zobo.php-intellisense"</span><span style="--shiki-dark:#D4D4D4;--shiki-light:#000000">]</span></span>
<span class="line"><span style="--shiki-dark:#D4D4D4;--shiki-light:#000000">}</span></span>
<span class="line"></span></code></pre>
<p>When installing an Extension Pack, VS Code will now also install its extension dependencies.</p>
<p>Extension packs should be categorized in the <code>Extension Packs</code> Marketplace category:</p>
<pre class="shiki" data-lang="json" shiki-themes dark-plus light-plus" style="--shiki-dark:#D4D4D4;--shiki-light:#000000;--shiki-dark-bg:#1E1E1E;--shiki-light-bg:#FFFFFF" tabindex="0"><code><span class="line"><span style="--shiki-dark:#D4D4D4;--shiki-light:#000000">{</span></span>
<span class="line"><span style="--shiki-dark:#9CDCFE;--shiki-light:#0451A5">  "categories"</span><span style="--shiki-dark:#D4D4D4;--shiki-light:#000000">: [</span><span style="--shiki-dark:#CE9178;--shiki-light:#A31515">"Extension Packs"</span><span style="--shiki-dark:#D4D4D4;--shiki-light:#000000">]</span></span>
<span class="line"><span style="--shiki-dark:#D4D4D4;--shiki-light:#000000">}</span></span>
<span class="line"></span></code></pre>
<p>To create an extension pack, you can use the <code>yo code</code> Yeoman generator and choose the <strong>New Extension Pack</strong> option. There is an option to seed the pack with the set of extensions you have currently installed in your VS Code instance. In this way, you can easily create an Extension Pack with your favorite extensions, publish it to the Marketplace, and share it with others.</p>
<p>An Extension Pack should not have any functional dependencies with its bundled extensions and the bundled extensions should be manageable independent of the pack. If an extension has a dependency on another extension, that dependency should be declared with the <code>extensionDependencies</code> attribute.</p>
<h2 id="extension-uninstall-hook" data-needslink="extension-uninstall-hook">Extension uninstall hook</h2>
<p>If your extension has some clean up to be done when it is uninstalled from VS Code, you can register a <code>node</code> script to the uninstall hook <code>vscode:uninstall</code> under <code>scripts</code> section in extension's package.json.</p>
<pre class="shiki" data-lang="json" shiki-themes dark-plus light-plus" style="--shiki-dark:#D4D4D4;--shiki-light:#000000;--shiki-dark-bg:#1E1E1E;--shiki-light-bg:#FFFFFF" tabindex="0"><code><span class="line"><span style="--shiki-dark:#D4D4D4;--shiki-light:#000000">{</span></span>
<span class="line"><span style="--shiki-dark:#9CDCFE;--shiki-light:#0451A5">  "scripts"</span><span style="--shiki-dark:#D4D4D4;--shiki-light:#000000">: {</span></span>
<span class="line"><span style="--shiki-dark:#9CDCFE;--shiki-light:#0451A5">    "vscode:uninstall"</span><span style="--shiki-dark:#D4D4D4;--shiki-light:#000000">: </span><span style="--shiki-dark:#CE9178;--shiki-light:#A31515">"node ./out/src/lifecycle"</span></span>
<span class="line"><span style="--shiki-dark:#D4D4D4;--shiki-light:#000000">  }</span></span>
<span class="line"><span style="--shiki-dark:#D4D4D4;--shiki-light:#000000">}</span></span>
<span class="line"></span></code></pre>
<p>This script gets executed when the extension is completely uninstalled from VS Code which is when VS Code is restarted (shutdown and start) after the extension is uninstalled.</p>
<p><strong>Note</strong>: Only Node.js scripts are supported.</p>
<h2 id="useful-node-modules" data-needslink="useful-node-modules">Useful Node modules</h2>
<p>There are several Node.js modules available on npmjs to help with writing VS Code extensions. You can include these in your extension's <code>dependencies</code> section.</p>
<ul><li><a href="https://www.npmjs.com/package/vscode-nls" class="external-link" target="_blank">vscode-nls</a> - Support for externalization and localization.</li>
<li><a href="https://www.npmjs.com/package/vscode-uri" class="external-link" target="_blank">vscode-uri</a> - The URI implementation used by VS Code and its extensions.</li>
<li><a href="https://www.npmjs.com/package/jsonc-parser" class="external-link" target="_blank">jsonc-parser</a> - A scanner and fault tolerant parser to process JSON with or without comments.</li>
<li><a href="https://www.npmjs.com/package/request-light" class="external-link" target="_blank">request-light</a> - A light weight Node.js request library with proxy support</li>
<li><a href="https://www.npmjs.com/package/@vscode/extension-telemetry" class="external-link" target="_blank">vscode-extension-telemetry</a> - Consistent telemetry reporting for VS Code extensions.</li>
<li><a href="https://www.npmjs.com/package/vscode-languageclient" class="external-link" target="_blank">vscode-languageclient</a> - Easily integrate language servers adhering to the <a href="https://microsoft.github.io/language-server-protocol" class="external-link" target="_blank">language server protocol</a>.</li>
