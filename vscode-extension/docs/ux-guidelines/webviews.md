			<main class="docs-main-content body"><h1>Webviews</h1>
<p>If you need to display custom functionality that is beyond what the VS Code API supports, you can use <a href="/api/extension-guides/webview">webviews</a>, which are fully customizable. It's important to understand that webviews should only be used if you absolutely need them.</p>
<p><strong>✔️ Do</strong></p>
<ul><li>Only use webviews when absolutely necessary</li>
<li>Activate your extension only when contextually appropriate</li>
<li>Open webviews only for the active window</li>
<li>Ensure all elements in the view are themeable (see the <a href="https://github.com/microsoft/vscode-extension-samples/blob/main/webview-view-sample/media/main.css" class="external-link" target="_blank">webview-view-sample</a> and <a href="/api/references/theme-color">color tokens</a> documentation)</li>
<li>Ensure your views follow <a href="/docs/configure/accessibility/accessibility">accessibility guidance</a> (color contrast, ARIA labels, keyboard navigation)</li>
<li>Use command actions in the toolbar and in the view</li>
</ul><p>❌ Don't</p>
<ul><li>Use for promotions (upgrades, sponsors, etc.)</li>
<li>Use for wizards</li>
<li>Open on every window</li>
<li>Open on extension updates (ask via a Notification instead)</li>
<li>Add functionality that is unrelated to the editor or workspace</li>
<li>Repeat existing functionality (Welcome page, Settings, configuration, etc.)</li>
</ul><h2 id="webview-examples" data-needslink="webview-examples">Webview examples</h2>
<p><strong>Simple Browser</strong></p>
<p>This extension opens a browser preview for the editor to the side.</p>
<p><img src="/assets/api/ux-guidelines/examples/webview-browser.png" alt="Weview sample - Browser" loading="lazy"></p>
<p><em>This example shows VS Code Web being developed right inside VS Code. A Webview panel is used to render a browser-like window.</em></p>
<p><strong>Pull Request</strong></p>
<p>This extension shows pull requests for the repository of the workspace in a custom tree view and then uses a webview for a detail view of the pull request.</p>
<p><img src="/assets/api/ux-guidelines/examples/webview-pull-request.png" alt="Webview sample - Pull Request" loading="lazy"></p>
<h2 id="webview-views" data-needslink="webview-views">Webview views</h2>
<p>You can also place webviews into any view container (sidebar or panel) and these elements are called <a href="/api/references/vscode-api#WebviewView">webview views</a>. The same webview guidance applies to webview views.</p>
<p><img src="/assets/api/ux-guidelines/examples/webview-view.png" alt="Webview View" loading="lazy"></p>
<p><em>This webview view shows content for creating a pull request that uses dropdowns, inputs, and buttons.</em></p>
