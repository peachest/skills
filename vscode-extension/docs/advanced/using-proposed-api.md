			<main class="docs-main-content body"><h1>Using Proposed API</h1>
<p>At Visual Studio Code, we take Extension API compatibility seriously. We give our best effort to avoid breaking API changes, and extension authors could expect published extensions to continue to work. However, this puts great limitation on us: once we introduce an API, we cannot easily change it anymore.</p>
<p>Proposed APIs solve the problem for us. Proposed APIs are a set of unstable APIs that are implemented in VS Code but not exposed to the public as stable APIs does. They are <strong>subject to change</strong>, <strong>only available in Insiders distribution</strong> and <strong>should not be used in published extensions</strong>. Nevertheless, extension authors could test these new APIs in local development and provide feedback for VS Code team to iterate on an API. Eventually, proposed APIs find their way into the stable API and becomes available for all extensions.</p>
<h2 id="using-a-proposed-api" data-needslink="using-a-proposed-api">Using a proposed API</h2>
<p>These are the steps for testing a proposed API in local extension development:</p>
<ul><li>Use <a href="/insiders">Insiders</a> release of VS Code.</li>
<li>To your <code>package.json</code>, add <code>"enabledApiProposals": ["&lt;proposalName&gt;"]</code>.</li>
<li>Copy the corresponding <a href="https://github.com/microsoft/vscode/blob/main/src/vscode-dts" class="external-link" target="_blank">vscode.proposed.&lt;proposalName&gt;.d.ts</a> files into your project's source location.</li>
</ul><p>The <a href="https://github.com/microsoft/vscode-dts" class="external-link" target="_blank">@vscode/dts</a> CLI utility allows you to quickly download the latest <code>vscode.proposed.&lt;proposalName&gt;.d.ts</code> for extension development. It downloads definition files by the proposals listed in your <code>package.json</code> file.</p>

<h2 id="proposed-api-incompatibility" data-needslink="proposed-api-incompatibility">Proposed API incompatibility</h2>
<p>On the main branch, the <code>vscode.proposed.&lt;proposalName&gt;.d.ts</code> is always compatible with <code>vscode.d.ts</code>. However, when you add <code>vscode.proposed.&lt;proposal&gt;.d.ts</code> to your project that uses <code>@types/vscode</code>, the latest <code>vscode.proposed.&lt;proposal&gt;.d.ts</code> might be incompatible with the version in <code>@types/vscode</code>.</p>
<p>You can solve this issue by either:</p>
<ul><li>Remove dependency on <code>@types/vscode</code> and use <code>npx @vscode/dts main</code> to download <code>vscode.d.ts</code> from <code>microsoft/vscode</code> main branch.</li>
<li>Use <code>@types/vscode@&lt;version&gt;</code> and also use <code>npx @vscode/dts dev &lt;version&gt;</code> to download the <code>vscode.proposed.&lt;proposal&gt;.d.ts</code> from an old branch of <code>microsoft/vscode</code>. However, be careful as the API might have changed in the latest version of VS Code Insiders.</li>
</ul><h2 id="sharing-extensions-using-the-proposed-api" data-needslink="sharing-extensions-using-the-proposed-api">Sharing extensions using the proposed API</h2>
<p>While you should not publish extensions using the proposed API on the Marketplace, you can still share your extension with your peers by packaging and sharing your extension.</p>
<p>To package your extension, you can run <code>vsce package</code> to create a VSIX file of your extension. You can then share this VSIX file to others to install the extension in their VS Code.</p>
<p>To install an extension from a VSIX file, you would go into the Extensions view, select the <strong>...</strong> ellipsis <strong>View and More Actions</strong> button, and select <strong>Install from VSIX</strong>.</p>
<p>Selecting the <strong>Install from VSIX</strong> menu item is shown in the short video below.</p>
<p><img src="/assets/api/advanced-topics/proposed-api/install-from-vsix.gif" alt="Demo showing a user going into the Extensions view to find the Install from VSIX menu item" loading="lazy"></p>
<p>For extensions using the proposed API, there are a couple more steps to enable your extension. After installing from your VSIX, you need to quit and relaunch VS Code Insiders from command line with <code>code-insiders . --enable-proposed-api=&lt;YOUR-EXTENSION-ID&gt;</code> in your project folder.</p>
<p>If you'd like to set it so that your extension using the proposed API is always available to use on every launch of VS Code Insiders, you can run the <strong>Preferences: Configure Runtime Arguments</strong> command to edit the <code>.vscode-insiders/argv.json</code> file to set a list of enabled extensions.</p>
