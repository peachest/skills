# Re-ask

把一个提问或一段产出从「只对作者上下文可读」重写成「读者可独立阅读」。读者没有作者的会话记忆、没读过前置文档、没共建过压缩术语——这是所有重写场景的唯一病根。

## 定位对象

- **有参数**：参数即对象（问题原文、文档路径、或「刚才那个 ask_user」「上一条回复里的 Q2」）。
- **无参数**：回溯当前会话最近一次提问（`ask_user` / `contact_supervisor` 调用，或最近一条回复末尾的问句）；如果最近没有提问、只有产出（报告/解释/概念段），则对象是那段产出。回溯结果通过产出本身暴露——读者看到四段/三段重写自然知道定位对不对，定位错了说「不是这个」即重定位，不加确认轮。

先判断对象类型，走对应分支：

## 分支一：重问（对象是问题）

把问题重写为四段。字段名**读者中立、无第一人称代词**：

```
**背景**：这个问题接在哪件事后面（重述，不写「如上一轮所说」）
**已知**：提问方已经掌握了什么（含证据来源）
**隐含的问题**：字面问题背后真正要问的是什么——经常不是问题字面本身
**答案影响**：答案会改变哪个决定
```

对会话场景：重写完成后**直接发起 `ask_user`**，问题正文带四段，一步到位。对文档场景（问题清单/提案文档）：原地改写，每题套四段；文档含 3 题以上时在开头加一节「现状速览」（目标 / 已定事实 / 暂定方案 / 待定项），让读者 30 秒站上与作者相同的信息水平线。

## 分支二：重解释（对象是产出）

把概念、报告段、公式、指标重写为三段：

```
**在哪用**：这个词/数字/结论出现在刚才哪句话里，起什么作用
**指什么**：在双方共享的语境下它到底指什么——不用术语解释术语
**为什么需要它**：没有它会怎样，或它解决什么具体问题
```

公式和数字必须落回具体含义（「这个比值 >1 意味着每一步白赚了 N 个 token」），不允许停留在符号推导。

## 红线（两个分支共用）

- **禁止引用「上一轮」「如前所述」**——重写的意义就是把背景带在身边。每处指代要么重述，要么给可点开的指针（文件路径 + 节名）。
- **禁止用术语定义术语**（「订阅谓词是一种谓词订阅机制」零信息量）。
- **禁止隐喻**（本仓全局规范已要求大白话，此处重申为硬约束：重写产出里隐喻计数必须为零）。
- **禁止压缩术语**：「两套生命周期」要写成「池和推理实例是两个独立增删的东西，不是一个扩缩容按钮」。
- **禁止超出对方表达过的意图**：重写不扩大问题范围、不加对方没问的分支。

重写产出以正文直接给出，不加「以下是重写」之类的元话语。

## 边界

- **重述当前进度/剩余任务**（「大白话说明剩余任务」）不属于本 skill：那是对进行中任务的重入场，走 orient / 日报链路。若用户要的其实是这个，指路即可。
- **stress-test 一个计划**（多轮追问挖决策树）走 grilling：re-ask 是单发重写，不开启追问循环。
