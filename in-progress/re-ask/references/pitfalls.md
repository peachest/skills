# Pitfalls — 四类「缺隐含上下文」病型

来源：2026-10 全库 session 挖掘（5627 sessions，183 条用户纠偏消息；数据在挖掘 session 的 `~/tmp/implicit-question-mining/`）。每型带真实触发原话——重写前后用它自查。

## A. 引用上轮而不重述（重问场景主病）

问题引用只有提问方自己知道的状态：「等你对上一轮三个开放点表态」「T02 的 3 个方案需要你决策」。同一 session 跨 5 天出现 9 次「重新问问题，什么开放点？」——用户每次都要追问开放点是什么。

**自查**：重写后的每个指代（「上一轮」「那三个方案」「之前说的 X」）是否都已重述或给出可点开的指针？恢复过的 session（compact 后）是重灾区——用户可能连 agent 在说什么都不知道。

## B. 问题埋在长报告里（重问场景次病）

问题出现在几十行密集汇报的末尾（「……这条也值得写进 spec。`#19` 现在是 7 场景全绿，等你表态后即可关票」）。读者面对一堵墙，问题本身找不到，触发「重新问问题」。

**自查**：重问时问题是否以独立块出现、一眼可见？汇报和提问不共用一段。文档场景的对策是「现状速览」节 + 每题独立四段。

## C. 用术语解释术语 / 压缩术语（重解释场景主病）

「什么是订阅谓词？——一种谓词订阅机制」零信息量。用户原话「请大白话解释清楚关联的上下文」「不要使用压缩后的术语，不要使用隐喻」在语料中出现多次；一次会话用户被逼到第三轮才让 agent 明白问题本身看不懂。

**自查**：每个术语的定义句里是否还藏着未解释的术语？把定义念给「第一次接触该领域的人」听（一条真实用户指令：「你要知道听众对 <领域> 没有任何经验，第一次接触」）。隐喻计数必须为零。

## D. 超出对方表达过的意图

用户只要「footer 显示 daemon 存活/死亡，没有更多状态」，agent 的提问隐含了更多设计假设，触发「大白话问问题」纠偏范围。

**自查**：重写是否只服务对方表达过的需求？不扩范围、不加分叉、不加「顺便问一下」。

## 边界外溢记录（本 skill 不接，留指针）

- 「大白话说明当前剩余任务」跨 8 个 session 出现 10 次——重入场需求，正典在 orient/日报链路。规律：进度叙述四要素 = 当前在哪 / 已定什么 / 暂定什么 / 剩什么。
- 「你把我搞混了，完全不知道你在干什么。重新说明」出现 3 次——方向级丢失（不是措辞差而是叙事丢失），重写也救不了，应回到 orient 重收现状。
